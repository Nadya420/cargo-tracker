# Как защитить проект перед преподавателем

## Что показать

Преподаватель должен увидеть связь «требование из задания → функция → работающий пример». На фотографиях нет подробной шкалы оценивания, поэтому обещать максимальный балл нельзя. Сильная защита опирается на работающий сценарий, понимание архитектуры и точные ответы о возможностях версии.

В презентации остаются все 19 слайдов, без отдельного сокращённого режима. Для регламента 3–5 минут комментируйте их коротко и не читайте весь текст. Ниже приведён рассказ примерно на 4 минуты 20 секунд с живой демонстрацией. Дополнительный разбор можно продолжить по вопросам преподавателя. Для быстрого перехода к нужному разделу используйте оглавление «Все слайды».

## Две версии одного учебного проекта

| Что показываем | Как работает | Что важно объяснить |
|---|---|---|
| Демонстрационный сайт GitHub Pages | HTML/CSS/JavaScript, данные в `localStorage` браузера посетителя | Учебный вход выполняется на клиенте. Реальной серверной границы доступа нет. Данные не общие между устройствами. Время берётся с компьютера посетителя. |
| Локальная серверная версия | Браузер, Python HTTP API, SQLite | Сервер проверяет владельца груза, хранит хеши паролей и записывает время. Данные сохраняются в файле базы. |

На фото задания указан GitHub Pages: Build and deployment, ветка `main`, папка `/ (root)`. Pages раздаёт статические файлы, но не запускает Python. Поэтому статическая демонстрация нужна для показа по ссылке, а серверная версия отдельно подтверждает работу Python и SQLite.

Публикация выполняется в Nadya420/cargo-tracker из аккаунта владелицы. Статус нужно подтвердить после фактической загрузки и успешного развёртывания Pages.

## Подготовка до занятия

1. Выберите, какую версию покажете живьём. По условию с Pages основной вариант, фактически опубликованный сайт. Пока публикация не завершена, используйте локальный резерв и прямо обозначайте его статус.
2. До защиты владелица репозитория или участник с нужными правами должны загрузить новую версию в `Nadya420/cargo-tracker`. После этого в настройках Pages выбрать источник развёртывания из ветки, ветку `main`, папку `/ (root)` и сохранить. Дождаться успешной сборки и открыть фактическую ссылку из настроек GitHub. Не предъявлять старый репозиторий как доказательство новой публикации.
3. Для сайта проверьте демонстрационный вход, создание груза, обновление, журнал и CSV на том же компьютере и в том же браузере, где будете защищаться. Демонстрационный вход: `demo` / `demo12345`. Он одинаков в обеих версиях. В демоверсии не используйте личные пароли.
4. Откройте презентацию отдельной вкладкой. Локальный `presentation.html` можно открыть без Python. Перелистывайте все слайды последовательно. Кнопка «Все слайды» открывает оглавление, а не сокращённый режим.
5. Подготовьте локальный Python-резерв: откройте терминал в папке с `server.py`, выполните `python3 server.py --demo` и откройте `http://127.0.0.1:8080`. На Windows можно выполнить `py -3 server.py --demo`. Вход серверной версии: `demo` / `demo12345`. Не закрывайте терминал во время работы.
6. Если порт 8080 занят, используйте `python3 server.py --demo --port 8081` и адрес с портом 8081. Саму серверную версию открывайте через этот адрес, не двойным щелчком по `index.html`.
7. Откройте исходники `server.py`, `app.js` и `test_server.py`, README и документ требований. Начните с результата в интерфейсе, код оставьте для объяснения реализации.
8. Для защиты подготовьте новый номер груза, например `DEF-2026-1120-01`. Если он уже существует, измените последний суффикс. Отрепетируйте заполнение формы.
9. Проверьте «Скачать CSV» и открытие файла в табличном редакторе. Содержимое CSV серверной версии прошло интеграционные тесты. Статическую версию и скачивание кнопкой нужно проверить отдельно на компьютере показа.
10. Проверьте читаемость на проекторе. В узком окне таблица прокручивается горизонтально. Возьмите архив, презентацию и реальные скриншоты на флешке.

Для GitHub Pages нужен интернет. Локальная Python-версия работает без подключения к сети. Записи из Pages автоматически не появятся в Python-базе и наоборот.

## Если преподаватель разрешит подробный разбор

Продолжайте ту же презентацию, без переключения режима. Через оглавление вернитесь к нужному слайду:

- Схема данных: в Python один пользователь связан со многими грузами, один груз со многими событиями истории.
- Идентификатор: внутренний `id` и пользовательский номер `tracking` решают разные задачи.
- Время: отметка сохранения отличается от времени физического события перевозки. В Pages она зависит от часов браузера, в Python от часов сервера.
- Доступ: клиентский учебный вход не обеспечивает изоляцию на уровне сервера. Серверная версия проверяет владельца в SQL-запросах.
- Хранение: `localStorage` принадлежит браузеру посетителя и может быть очищен. SQLite находится на машине, где запущен Python. Данные этих версий не синхронизируются.

## Если что-то не открылось

| Ситуация | Действие и честное пояснение |
|---|---|
| Ссылка Pages не открывается | Проверьте публикацию и интернет. Пока сайт не развёрнут, используйте локальный резерв и обозначьте это. |
| На другом компьютере нет ваших грузов Pages | Это ожидаемо: у другого браузера своё `localStorage`. Покажите, что он создаёт собственные демонстрационные записи. |
| После очистки данных сайта записи Pages пропали | Локальное хранилище браузера очищено. Не называйте его общей серверной базой. |
| Локальный адрес недоступен | Проверьте терминал и запустите Python-сервер. |
| Порт 8080 занят | Запустите с `--port 8081` и поменяйте адрес. |
| Номер уже существует | Используйте новый суффикс. Это пример предотвращения дубликата. |
| После перезапуска Python требуется вход | Это ожидаемо: SQLite сохраняется, сессии находились в памяти процесса. |
| Быстро восстановить показ не удалось | Покажите реальные скриншоты и код. Скажите: «Сейчас показываю ранее полученный снимок, живой запуск требует исправления». |

## Как отвечать уверенно

Сначала дайте короткий ответ, затем покажите подтверждение в интерфейсе или коде. Каждый технический ответ привязывайте к версии: Pages или Python. Не переносите свойства серверной авторизации на браузерную демонстрацию.

Перед защитой самостоятельно разберите три действия: создание записи, сохранение истории и проверку доступа в Python. Если работа готовится для подруги, именно выступающая должна уметь повторить эти шаги и объяснить код. Заготовки находятся в `TEACHER_QA.md`.

**Через требование:** «В задании нужно было реализовать учёт грузов с журналом и временем. Покажу, где проверяется каждый пункт».

**Через демонстрацию:** «Сейчас зарегистрирую груз и изменю его статус. На этом примере будут видны основные функции».
