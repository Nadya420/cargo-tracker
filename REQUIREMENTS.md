# Требования к проекту CargoFlow

## 1. Назначение

**Тема:** «Система отслеживания грузов».

**Цель:** создать учебное веб-приложение для регистрации международных грузов, просмотра состояния и восстановления последовательности обновлений.

**Пользователь:** оператор, который вручную ведёт собственный реестр. Отдельных ролей администратора, перевозчика и таможенного инспектора нет.

**Результат:** карточка груза, направление перевозки, статус/местоположение, временные отметки журнала и CSV-файл реестра.

Источники задания: фотографии `IMG_9324.HEIC`, `IMG_9325.HEIC`, `IMG_9326.HEIC`. Ниже сформулированы проверяемые требования и границы реализации. Оценку выставляет преподаватель, а не программа.

## 2. Два варианта реализации

| Свойство | Python/SQLite | GitHub Pages |
|---|---|---|
| Назначение | Полный локальный серверный прототип | Показ по опубликованной интернет-ссылке |
| Логика | Python API | JavaScript-адаптер `browser-demo.js` |
| Хранение | SQLite на компьютере сервера | localStorage конкретного браузера и адреса сайта |
| Вход | Серверная проверка, cookie-сессия | Учебная проверка и sessionStorage |
| Изоляция | Сервер проверяет владельца каждой записи | Адаптер отбирает записи учебного пользователя, но владелец браузера может изменить хранилище |
| Часы | Серверное время | Время устройства |
| Синхронизация | Единая база запущенного сервера | Нет общего реестра между устройствами |

Интерфейс и основные пользовательские операции одинаковы. Данные этих вариантов не синхронизируются. Браузерная версия не эквивалентна защищённой серверной авторизации и предназначена только для вымышленных учебных данных.

## 3. Функциональные требования и приёмка

| Код | Требование | Критерий приёмки |
|---|---|---|
| FR-01 | **Регистрация груза.** Создать карточку с номером, названием, странами отправления/назначения, статусом и местоположением. | После сохранения карточка появляется в реестре и имеет начальное событие журнала. Пустые обязательные поля отклоняются. |
| FR-02 | **Идентификация.** Карточка имеет внутренний ID и номер отслеживания в реестре пользователя. | Повторный номер у того же пользователя отклоняется. Другой учебный пользователь может использовать тот же номер. По номеру можно найти и открыть нужную карточку. |
| FR-03 | **Направление перевозки.** Хранить страны отправления и назначения. | Ввести «Китай» и «Россия», сохранить и повторно открыть карточку. Обе страны совпадают с введёнными. |
| FR-04 | **Текущее состояние.** Показывать статус и местоположение, разрешать обновление с комментарием. | Сохранить статус «На таможне» и «Учебный терминал». Новые значения видны в карточке и реестре. Статус вне списка отклоняется. |
| FR-05 | **Отслеживание времени.** Автоматически фиксировать момент сохранения состояния и каждого события журнала. | После создания и обновления есть две временные отметки. `updated_at` совпадает со временем последнего события. В Python отметки назначает сервер, в браузерной версии устройство. |
| FR-06 | **Журнал изменений.** Сохранять начальное состояние и последующие сохранения с датой, временем, статусом, местоположением и комментарием. | После создания и двух обновлений видны три события, новые выше старых. Предыдущие записи не исчезают. |
| FR-07 | **Вход и разделение реестров.** Предоставить регистрацию, вход и выход. | Неверный пароль отклоняется, после входа виден реестр пользователя, после выхода снова требуется вход. Серверный API запрещает чтение/изменение чужих карточек. В статическом варианте разделение учебное, не защита от владельца браузера. |
| FR-08 | **CSV.** Выгрузить весь реестр текущего пользователя. | CSV содержит семь колонок: номер, груз, откуда, куда, статус, местоположение, обновлено UTC. Читаются кириллица, кавычки и разделители. Текущий фильтр не ограничивает экспорт. |
| FR-09 | **Поиск и фильтрация.** Найти номер, название, страны или местоположение, отобрать статус. | По известному номеру находится запись. Фильтр «На таможне» оставляет только этот статус. Сброс условий восстанавливает реестр. |
| FR-10 | **Сохранение данных.** Сохранять карточки, журнал и учебные учётные записи между открытиями. | Python: перезапустить с тем же файлом SQLite, снова войти и найти груз. Pages: перезагрузить страницу в том же браузере без очистки хранилища и найти груз. |

FR-01, FR-02, FR-03, FR-05 и FR-06 соответствуют основному списку с фотографий. FR-04 раскрывает отслеживание состояния. FR-07 и FR-08 соответствуют дополнительным пунктам про авторизацию и CSV. FR-09 и FR-10 поддерживают удобство и воспроизводимость.

### Точная трактовка времени

Реализовано время **внесения сведений**. UTC-строки хранятся в `updated_at` и `history.at`, браузер показывает их в часовом поясе устройства. Первое событие обычной новой карточки фиксирует регистрацию, следующие события фиксируют сохранения.

Эти отметки не подтверждают фактическое прибытие транспорта. Нет ETA, планового срока, просрочки, длительности пути и расчёта времени таможенного оформления. Если преподаватель подразумевает контроль сроков, это отдельное расширение. В браузерной версии отметки дополнительно зависят от настройки часов устройства.

### Точная трактовка журнала

Журнал хранит снимок `status`, `location`, `note`, `at`. Он не содержит автора каждой операции и полного сравнения «было/стало» всех полей. Через текущий интерфейс номер, название и страны после создания не редактируются. Повторное сохранение прежнего состояния тоже создаёт событие. Владелец SQLite или localStorage может изменить данные напрямую, неизменяемость журнала не гарантируется.

### Страны, номера и статусы

Номер уникален только в реестре пользователя, не глобально и не в международной системе перевозчика. Страны вводятся свободным текстом. Пять разрешённых статусов: «Зарегистрирован», «В пути», «На таможне», «Выпущен», «Доставлен». Обязательной последовательности переходов нет. Сведения о допустимости перевозки и таможенные юридические решения система не определяет.

## 4. Технические и нефункциональные требования

| Код | Условие | Фактическая граница |
|---|---|---|
| NFR-01 | Веб-интерфейс на HTML/CSS/JavaScript, программная логика по заданию. | Python-версия содержит настоящий HTTP API. Версия Pages реализует сценарии адаптером в браузере. |
| NFR-02 | Воспроизводимый локальный запуск. | Python 3 со стандартной библиотекой для сервера. Современный браузер с Web Crypto и разрешёнными хранилищами для статического показа. |
| NFR-03 | Проверка ввода. | Шесть полей груза 1–160 символов после удаления краевых пробелов, комментарий до 500, логин 3–40, пароль 8–128, статус из списка. Сервер проверяет независимо от интерфейса. В Pages проверка работает в JavaScript. |
| NFR-04 | Пароли не хранятся открытым текстом. | В обоих вариантах соль и PBKDF2-SHA256. Только Python выполняет проверку на доверенной серверной стороне. Хеш в localStorage не превращает учебный вход в защиту браузерного хранилища. |
| NFR-05 | Исходники, инструкция и проверяемые результаты. | README, требования, тесты Python и браузерного адаптера, реальные снимки, презентация и материалы защиты. Результаты в [QA.md](QA.md). |
| NFR-06 | Возможность статической публикации. | Относительные пути интерфейса, `index.html` и `.nojekyll` в корне. Источник GitHub Pages: `main` / `/(root)`. Публикация подтверждена, проверено открытие по внешней ссылке. |

Нагрузка, время ответа и число одновременных пользователей в задании не определены и не измерены. Производственная готовность не заявляется.

## 6. Сценарий приёмки на защите

1. Назвать показываемую версию: серверная либо браузерная.
2. Войти `demo / demo12345`.
3. Создать вымышленный груз с новым номером и обязательными полями.
4. Найти его по номеру и сверить страны.
5. Изменить статус и местоположение, добавить комментарий.
6. Показать начальное и новое событие, даты и время.
7. Выгрузить CSV и проверить созданный номер в файле.
8. Для сохранности перезагрузить страницу. В серверном варианте при необходимости перезапустить Python с той же базой и снова войти.

Связь «требование, действие, наблюдаемый результат» показывает выполнение условий. Возможный балл и соответствие трактовке срока доставки определяет преподаватель.
